## Indexation and canonical state

Fresh URL Inspection is healthy for the market homepage, general consultation, driving certificate, Telmo Coelho and Vitor Pais. Google-selected canonicals match declared canonicals for those samples. Pedro is the only unresolved recrawl case.

No robots, proxy, canonical, redirect or sitemap code change was justified. Existing route conventions remain:

- `frontend/proxy.ts`, not `middleware.ts`;
- redirects in `frontend/next.config.ts`, evaluated before proxy;
- canonical/hreflang generated by existing metadata helpers;
- public sitemap logic tested in the frontend package;
- private portal routes remain outside this SEO work.

## Structured data

The repository already emits visible-content-aligned Organization, Service, physician/clinician and breadcrumb patterns. No new review, rating, clinic or location schema was added. Continue to enforce:

- Physician only for a verified real clinician;
- MedicalClinic only for a real physical clinic;
- no aggregate rating without eligible visible evidence;
- FAQ markup only for visible reviewed questions;
- price/offer data only from current visible product values;
- one consistent canonical entity per URL.

## Performance and crawl

The audited Portugal homepage responded in about 353 ms in the provider crawl. The 75 slow-response issues were not scoped to Portugal in the returned slice, so they are a queue for a route-contained performance audit, not an implementation mandate.

Image SEO on the Portugal page is partly content-driven. English clinician image titles/descriptions are CMS data gaps. The component correctly uses localized/record values and accessible fallbacks; production translations must be supplied rather than adding another code fallback.

## Localization fix

Changed flow:

`common.doctors locale JSON → doctorCardI18n() → DoctorCard`

Added `viewProfileAria` and `credentialsLabel` to the shared card strings. The overlay link now resolves `{name}` through the localized value, and the credential heading uses the locale bundle. The explicit `viewProfileAriaLabel` prop still overrides the shared string when a template has a reason to do so.
