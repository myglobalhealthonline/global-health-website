Audit date: 2026-07-11 · Static analysis · Pattern legend: A=Simple responsive list · B=Primary columns + details drawer · C=Column-priority table · D=Mobile cards / desktop table (single config) · E=Dedicated detail page (list stays thin).

Context that applies to every table row below:
- Blanket rule `portal.css:5066-5082` forces `min-width:720px` on every `.gh-admin-main` table.
- Table↔card switch is a fixed `@media (max-width:760px)` (`portal.css:911-942`) → **761–1023px gap** where forced-wide tables scroll horizontally although a working card layout exists.
- "Dual markup" = desktop table + separate `PortalMobileCard` list repeating labels/formatting (target for single-config `ColumnPriorityTable`).
- No portal list uses a kebab/dropdown row menu today; all row actions are inline buttons/links (grep: Radix only in country-picker).
