## ID / documentation inconsistencies found during synthesis (flagged, not corrected in the source files per instruction not to modify them)

1. **Two different issue-ID conventions coexist across the 17 files**: page-number-prefixed (`05-001`, `07-001`) vs section-number-prefixed (`UX-001`, `VIS-001`, `IH-001` on page 03; `CAL-04-001` on page 04). This makes cross-page ID references ambiguous without the filename as context — this synthesis always qualifies IDs with their page (e.g. "03/UX-001") where collision risk exists.
2. **`01-dashboard.md` §11 reuses the label "11-001"** for a page-01-local visual-design finding (the `AdminCard > SectionHeader` double-edge), which is easy to visually confuse with page 11's own `11-001` (Notifications' stale-badge bug) despite being completely unrelated findings on different pages.
3. **`05-availability.md` lists issue IDs 05-009, 05-010, 05-012 as accessibility items** that substantially restate 05-007/05-008/05-011 rather than introducing new findings (05-009 is explicitly "cross-listed as both UX and a11y" with 05-007) — treated as the same finding, not double-counted, in this synthesis's severity tallies.
4. **A factual claim in `03-appointment-details.md` does not hold up under verification**: UX-001's fix recommendation states the `UnsavedChangesGuard` primitive is "already used on other doctor pages (`doctor/profile/_components/edit-form.tsx`, `doctor/services/_components/service-selection-form.tsx`)." A grep across the entire `app/(doctor)` tree for `UnsavedChanges` returns **zero matches** — the primitive is not adopted anywhere in the doctor portal today (see `05-shared-component-impact-map.md` §9 for the full correction). This does not change the recommended fix (the primitive still exists and should still be reused), but the "already used elsewhere in the doctor portal" framing is incorrect and should not be repeated in implementation tickets.
5. **Missing sections**: no page file omits a required section entirely, but several mark specific subsections explicitly "not verified"/"code-derived only" rather than leaving them blank — this is the correct, honest pattern and was preserved rather than treated as a gap in this synthesis.
