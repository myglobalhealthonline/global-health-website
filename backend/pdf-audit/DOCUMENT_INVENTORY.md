# Document Inventory — Global Health

Every document/PDF/export/upload path in the system, verified against source (2026-07-09, branch `Dev-hassaan`).

Rendering engines in use: **HTML → PDF via Playwright/Chromium** (`htmlToPdfBuffer`) and **DOCX → PDF via LibreOffice (`soffice`)**. `pdf-lib@1.17.1` is declared in `backend/package.json` but imported nowhere — dead dependency, removable.

---

## A. Documents we generate (locally renderable — template-controlled)

### 1. Order fiscal documents — Invoice / Receipt / Invoice-Receipt / Credit Note
- **Format:** HTML → PDF (Chromium)
- **Generated by:** us
- **Code:** `backend/src/modules/invoices/invoice-pdf.ts` (`buildInvoiceHtml`, `renderInvoicePdfBuffer`, data via `buildInvoicePdfData`); orchestration in `generate-invoice.service.ts` (`renderAndSendInvoiceDoc`)
- **Template:** inline HTML string in `invoice-pdf.ts` (no template file)
- **Storage:** regenerated on demand — never stored; `Invoice` DB row is source of truth
- **Delivery:** email attachment; WhatsApp = **link only** (`resendInvoiceWhatsApp`); admin download (`admin-invoices.route.ts`)
- **Filename:** `invoice|receipt|credit-note-<invoiceNumber>.pdf`
- **i18n:** `INVOICE_LABELS` for ie/cz/sp/rm/pt (labels + per-country legal footer). PT excluded in production — InvoiceExpress issues the legal doc (see B.1)
- **Doc types (Prisma enum `InvoiceDocumentType`):** INVOICE, RECEIPT, INVOICE_RECEIPT, CREDIT_NOTE

### 2. Doctor-issued clinical documents
- **Types (Prisma enum `GeneratedDocumentType`):** ABSENCE_CERTIFICATE, EXAMS_PRESCRIPTION, PRESCRIPTION, CUSTOM_CERTIFICATE, OTHER
- **Format:** primary **DOCX → PDF via LibreOffice** (per-country .docx templates); fallback **HTML → PDF via Chromium**
- **Generated by:** us (doctor triggers from portal)
- **Code:** `generated-documents.service.ts` (`generateAppointmentDocument`), `docx-document-renderer.ts` (`renderDocxTemplatePdf`), `html-document-renderer.ts` (`renderDocumentPdf`), `document-template-utils.ts`
- **Templates:**
  - DOCX: `backend/assets/docx-templates/(IR|PT|ES|CZ|RO) <Type> Template _ Global Health.docx` (15 files, logos embedded in `word/media/`); profile map in `docx-template-profiles.ts`
  - HTML fallback: `backend/assets/document-templates/_default/*.html` + shared `partials/styles.html` (per-country dirs supported, only `_default` exists)
- **Extras:** QR codes injected (verification QR → `/verify/certificate/<id>`, upload-link QR for exams) via `qr-code.ts`; AlexBrush signature font (`backend/assets/fonts/AlexBrush-Regular.ttf`)
- **Storage:** S3/object storage, key `generated/<doctorId>/<apptId>/<uuid>/<fileName>` + `GeneratedDocument` DB row
- **Delivery:** email attachment to patient; upload-link via email + WhatsApp; doctor download `/api/doctor/documents/generated/:id/pdf`
- **Filename:** `<patientSlug>-<docTypeLabel>-<seq2>.pdf` (e.g. `Jane-Doe-exam-prescription-01.pdf`)
- **i18n:** per-country DOCX template (IR/PT/ES/CZ/RO); per-country legal text for cz/pt; HTML fallback resolves per-country dir else `_default`

### 3. Admin/doctor list reports
- **Format:** CSV (RFC4180), "Excel" (**hand-built SpreadsheetML 2003 XML served as `.xls`** — not real XLSX), PDF (Chromium)
- **Code:** `modules/reports/report-formatters.ts` (`serializeReport`, `toCsv`, `toExcelXml`, `renderReportPdf`); datasets in `report-datasets.ts`
- **Delivery:** admin download (`admin-reports.route.ts`), doctor download (`doctor-report-exports.route.ts`)
- **Filename:** `<base>.<csv|xls|pdf>`
- **i18n:** en-GB only

### 4. Audit log export
- **Format:** CSV — `routes/admin-audit-log.route.ts`; filename `audit-log-<YYYY-MM-DD>.csv`; admin download; en only

### 5. Newsletter subscribers export
- **Format:** CSV — `routes/newsletter.route.ts`; filename `newsletter-subscribers-<YYYY-MM-DD>.csv`; admin download

### 6. GDPR "my data" export
- **Format:** JSON — `routes/auth.route.ts`; filename `global-health-data-<userId>.json`; authenticated download

### 7. Sample-PDF dev script
- `backend/scripts/gen-sample-pdfs.ts` — renders all 4 invoice types + all 5 clinical types via the **HTML** path, IE only. Gap: never exercises the DOCX/LibreOffice path or non-IE countries.

## B. External-service documents (NOT locally redesignable)

### 1. Portugal legal InvoiceReceipt / credit note — **InvoiceExpress**
- `modules/invoices/pt-invoicexpress.service.ts` + `lib/invoice-express/client.ts` (create → finalize → email)
- Hosted by InvoiceExpress; we store only `order.invoiceExpressId`. InvoiceExpress emails it. **Styling controlled only inside the InvoiceExpress account settings (their web dashboard: logo + template options), not from our codebase.** Recommend uploading the Global Health logo + brand color there for consistency.

### 2. PT Stripe invoice data feed — `pt-stripe-invoice-data.ts` (Stripe custom_fields/metadata; data only, no document)

### 3. Subscription invoices — **Stripe**
- Stripe is system of record; webhook stores `hostedInvoiceUrl` + `pdfUrl` on `SubscriptionInvoice`. Patient portal links via `GET /api/me/invoices`. Branding limited to Stripe dashboard settings (logo, accent color under Branding).

### 4. Stripe charge receipts — `services/stripe-receipt.service.ts` → `charge.receipt_url`, external link only. Same: brandable only via Stripe dashboard Branding settings.

### 5. Make.com invoice webhook — data POST, no document.

### 6. National health-portal links (Healthmail/PEM/REMPE/eRecept…) — `country-portals.ts`, external URLs only.

## C. Uploaded files (document-shaped, never template-controlled)

All through `services/object-storage.ts` (S3 when configured, else local `.data/local-media`).

| Upload | By | Key pattern | DB |
|---|---|---|---|
| Doctor payout invoices | Doctor | `payout-invoices/<doctorId>/<period>__<uuid>-<safeName>` (`payout-invoice-storage.ts`) | none — S3 prefix listing only |
| Medical documents (reports/exam results) | Patient & doctor | `patient-docs/<profileId>/medical/<uuid>.<ext>` | `MedicalDocument` |
| Insurance doc | Patient | `patient-docs/<profileId>/insurance/<uuid>.<ext>` | `PatientProfile.insuranceDocumentKey` |
| ID document front/back | Patient | `patient-docs/<profileId>/id-document/<side>-<uuid>.<ext>` | `idDocumentKey`/`idDocumentBackKey` |
| Nationality/identity docs | Patient | `patient-docs/<profileId>/nationality-<slot>/…` | `PatientNationalityDocument` |
| Clinical appointment attachments | Doctor | `clinical/<doctorId>/<apptId>/<uuid>-<safeName>` | appointment-documents |
| Consultation chat attachments | Both | `patient-chat/<apptId>/<uuid>-<safeName>` | `ConsultationMessage.storageKey` |
| Legal document PDFs (T&C) | Admin | `LegalDocument.pdfPath`, public link | `LegalDocument` |

Doctor payout invoices: accepted formats governed by the upload route (`doctor-payout-invoices.route.ts`); admin downloads via `admin-payout-invoices.route.ts`.

## Notes
- WhatsApp never carries a document binary — always a link.
- Only clinical generated docs (A.2) + uploads (C) live in object storage; fiscal PDFs and exports are regenerated per request.
- Frontend also has a print page `/print/order-invoices/<id>` (browser-print rendition of the invoice) and `/verify/certificate/<id>`.
